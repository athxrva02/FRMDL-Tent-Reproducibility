Project (group): Reproduce a machine/deep learning research paper  [group] (60% of the grade)
We assume you have taken the "Machine and Deep Learning" core course. Please make sure you have experience with programming for machine and/or deep learning (eg: Python, numpy, pytorch) before you take the course; otherwise it will take too much extra time from you. 

Use Brightspace to register in teams of 2-3 students. Each team is assigned to a single teaching-assistant (TA) to guide you. You cannot do the project alone.

At the end of the course we will organize a "project presentation" session where every group can present their work to others. This presentation itself is not graded, and attendance is not mandatory, but it counts towards the "motivation" rubric in the project.

After week 4 your team should start on a deep learning reproducible project. Use week 1 - 4 to select which paper to (re)implement, and to prepare a reproduction plan with your TA, which you will discuss with your TA during the first meeting. The reproduction plan should include a rough division of tasks where you specify which team member does what. We will make a list of papers to reproduce available here, where some papers are co-supervised by an external researcher or a company, you can contact them for more information about what they want. If you wish to choose your own paper to reproduce: talk to a TA. At the end of the course you should submit a blog post about your reproducibility project. We will grade this blog post.

For writing your reproducibility blog, draw inspiration from the following sources:

Earlier projects are available here: https://reproducedpapers.org/

If you like the project, consider posting your blog post online to inform deep learning researchers here  https://reproducedpapers.org/  or elsewhere. You can use this project also to build your own portfolio online.

Consider sharing your controlled dataset here https://www.controlledexperimentsinml.org/
The grading is done according to these criteria:

    • 20%: Motivation: Good plan prepared and discussed with TA, meets TA sufficiently, attends the presentation session

    • 50%: Content: Show good efforts on trying to reproduce something

    • 30%: Exposition: write a clear blog post; address the value of doing a reproduction; state if your reproduction results uphold the main conclusions of the paper, or not, and what consequences this might have.

Reproducibility project guidelines
There are multiple criteria for reproducing a paper. The two main options are: 

Full re-implementation: Implemented the paper contribution without using pre-existing code. This will pass the project without any extra work needed.

Existing code: Replicate an existing code implementation. Additional criteria will be required. Please consult with your TA and see below.

When you submit your reproduction, you can select multiple criteria, each person should at least be responsible for 1 criteria:


Reproduced: Existing code was evaluated.

Hyperparams check: Evaluating sensitivity to hyperparameters.

New data: Evaluating different datasets to obtain similar results.

New algorithm variant: Evaluating a slightly different variant.

New code variant: Rewrote or ported existing code to be more efficient/readable.

Ablation study: Additional ablation studies.

In your submission make clear which criteria you used, and why. Each submission should briefly list what each person contributed (few lines).
